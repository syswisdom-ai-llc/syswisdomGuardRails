Atlassian Cloud Planned

Automatically create Jira tickets from data quality issues and post quality reports to Confluence pages. Connects GuardRails analysis results directly into your project tracking workflow.

Jira: Auto-Create Tickets from Quality Issues

When GuardRails finds critical issues (null rates, format errors, duplicates above threshold), the integration can POST to the Jira Cloud REST API to open a bug or task automatically.

Prerequisites

  1. Create an Atlassian API token

    Go to id.atlassian.com → Security → Create and manage API tokens. Copy the token (shown only once).

  2. Add to your .env file

    Add these three variables to .env in the project root:

    JIRA_BASE_URLe.g. https://yourcompany.atlassian.net
    JIRA_EMAILYour Atlassian account email
    JIRA_API_TOKENThe API token from Step 1
    JIRA_PROJECT_KEYe.g. DQ (your project's key in Jira)

Create a Jira Issue from a Quality Finding

# POST to Jira Cloud REST API v3
curl -X POST \
  "${JIRA_BASE_URL}/rest/api/3/issue" \
  -H "Authorization: Basic $(echo -n ${JIRA_EMAIL}:${JIRA_API_TOKEN} | base64)" \
  -H "Content-Type: application/json" \
  -d '{
    "fields": {
      "project": { "key": "DQ" },
      "summary": "Data Quality Alert: null rate 18% in customer_email column",
      "description": {
        "type": "doc",
        "version": 1,
        "content": [{
          "type": "paragraph",
          "content": [{ "type": "text", "text": "GuardRails detected 18% null rate in customer_email. Overall score: 73.2. Analysis ID: analysis_20260512_0941" }]
        }]
      },
      "issuetype": { "name": "Bug" },
      "priority": { "name": "High" }
    }
  }'

Azure DevOps Planned

Integrate data quality gates into Azure Pipelines. Fail a pipeline if quality score drops below your threshold, and automatically create Work Items from critical quality issues.

Environment Variables

AZURE_DEVOPS_ORGe.g. https://dev.azure.com/yourorg
AZURE_DEVOPS_PROJECTYour project name
AZURE_DEVOPS_PATPersonal Access Token (Work Items Read & Write scope)

Pipeline Quality Gate: azure-pipelines.yml

Add a GuardRails quality gate step to your Azure Pipeline. The pipeline will fail if the data quality score is below 75:

# azure-pipelines.yml
trigger:
  branches:
    include:
      - main

pool:
  vmImage: 'ubuntu-latest'

steps:
  - task: NodeTool@0
    inputs:
      versionSpec: '22.x'

  - script: npm install
    displayName: 'Install GuardRails dependencies'

  - script: |
      node server.js &
      sleep 3

      # Upload file and analyze
      RESULT=$(curl -s -X POST http://localhost:3000/analyze \
        -H "X-API-Key: $(dq_api_key)" \
        -F "file=@Data/test.csv")

      SCORE=$(echo $RESULT | node -e "
        let d=''; process.stdin.on('data',c=>d+=c);
        process.stdin.on('end',()=>{ const r=JSON.parse(d); process.stdout.write(String(r.overall_score||0)); })
      ")

      echo "Data Quality Score: $SCORE"

      if (( $(echo "$SCORE < 75" | bc -l) )); then
        echo "##vso[task.logissue type=error]Quality score $SCORE is below threshold 75"
        exit 1
      fi
    displayName: 'GuardRails Quality Gate'
    env:
      dq_api_key: $(DQ_API_KEY)

Postman Active

Import the GuardRails Postman collection to test all API endpoints interactively, run automated test suites with Newman, and share API documentation with your team.

Quick Start: Import the Collection

  1. Open Postman → Import

    Click Import in the top-left. Choose Raw text and paste the collection JSON below, or save it as guardrails-postman.json and import as a file.

  2. Set the Collection Variable

    Set baseUrl to http://localhost:3000 and apiKey to your dq_api_key value from .env.

  3. Run the Collection

    Click Run collection to execute all requests in sequence. Use Postman Environments to switch between local and production.

PostgreSQL: Export Table and Analyze

// lib/db-export.js (planned)
const { Client } = require('pg');
const { writeFileSync } = require('fs');
const FormData = require('form-data');
const fetch = require('node-fetch');

async function analyzeTable(tableName) {
  const client = new Client({
    host: process.env.DB_HOST,
    port: process.env.DB_PORT,
    database: process.env.DB_NAME,
    user: process.env.DB_USER,
    password: process.env.DB_PASSWORD,
  });

  await client.connect();

  // Fetch table as CSV
  const res = await client.query(`SELECT * FROM ${tableName} LIMIT 50000`);
  const headers = res.fields.map(f => f.name).join(',');
  const rows = res.rows.map(r => Object.values(r).join(','));
  const csv = [headers, ...rows].join('\n');

  writeFileSync('/tmp/export.csv', csv);
  await client.end();

  // Send to GuardRails
  const form = new FormData();
  form.append('file', Buffer.from(csv), { filename: `${tableName}.csv` });

  const result = await fetch('http://localhost:3000/analyze', {
    method: 'POST',
    headers: { 'X-API-Key': process.env.dq_api_key, ...form.getHeaders() },
    body: form,
  });

  return result.json();
}

module.exports = { analyzeTable };
⚠️
Never store database credentials in source code. Always use .env with dotenv, or an environment variable injected by your CI/CD system. Add .env to .gitignore.

HuggingFace Hub Active

Pull datasets directly from HuggingFace Hub into the GuardRails quality pipeline. No manual download needed. Search by keyword, inspect license and file list, then load any .csv or .json file in one click.

How It Works

GuardRails proxies three HuggingFace Hub API endpoints server-side and surfaces the results in the Upload tab. Dataset content is processed in-memory and never written to disk.

🔍 Search

Search HuggingFace Hub by keyword. Returns the top 20 datasets sorted by downloads. Click any result to jump straight to Inspect.

GET /hf/search?q=fraud+detection

🔎 Inspect

Fetch a dataset's metadata: license, gated status, description, and a filtered list of .csv/.json files available in the main branch.

GET /hf/inspect?dataset=owner/name

📥 Load & Analyze

Stream a specific file in-memory, proxy it to the SysWisdom analysis API, and return scored results. Logs a compliance record (dataset, file, reviewer, timestamp).

POST /hf/load

Setup: API Key

The HUGGINGFACE_API_KEY is optional for public datasets. You only need it for:

  • Gated datasets (requires accepted access request on huggingface.co)
  • Higher rate limits (unauthenticated requests are capped at ~100/hour per IP)
HUGGINGFACE_API_KEY Optional. hf_xxx read token from huggingface.co/settings/tokens 
# .env
HUGGINGFACE_API_KEY=hf_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx

Step-by-Step: Loading a Dataset

  1. Open the HuggingFace tab

    In the GuardRails Upload screen, click the 🤗 Hugging Face Dataset tab.

  2. Search or enter a dataset ID

    Use the search box (e.g. "tabular fraud ecommerce") or type a dataset ID directly: rajpurkar/squad or paste a full URL like https://huggingface.co/datasets/rajpurkar/squad.

  3. Inspect the dataset

    Click Inspect. GuardRails fetches the license, gated status, description, and lists all .csv/.json files available.

  4. Review the license

    A green badge means open (MIT, Apache, CC0, etc.). Orange means restricted; verify your use case before loading. Red means gated; see Gated Datasets below.

  5. Click Load on a file

    The file streams in-memory through the SysWisdom analysis API. Results appear in the Review Issues tab automatically.

Gated Datasets

Some datasets require you to agree to terms on huggingface.co before downloading:

  1. Request access on huggingface.co

    Visit the dataset page and click Agree and request access. Approval is automatic or manual depending on the dataset author.

  2. Add a read token to .env

    Generate a read-only token at huggingface.co/settings/tokens and add it to .env.

  3. Restart the server

    Run npm start again to load the new key. The gated dataset will now be accessible.

ℹ️
Dataset content is processed in-memory only and never stored on disk by GuardRails. Only the dataset name, file path, reviewer, and access timestamp are logged for compliance. The analysis result (scores + issues) is stored the same way as a regular file upload.

Rate Limits

Without a token: ~100 requests/hour per IP. With HUGGINGFACE_API_KEY: significantly higher. See huggingface.co/docs/hub/rate-limits.

AI Connectors Planned

GuardRails uses AI to generate fragility narratives, actionable fix code, and AI Readiness verdicts. Three providers are supported: Google Gemini (primary), OpenAI ChatGPT, and Anthropic Claude.

ℹ️
All AI connectors are optional. GuardRails scores data deterministically without AI. AI is called only for post-analysis narrative generation: understanding why scores are what they are, not computing them.

✨ Google Gemini Primary

Powers three GuardRails AI features: Chaos fragility narrative, AI Fix Suggestions, and AI Readiness Score verdict.

Enterprise-grade alternative. Claude 3.5 Sonnet excels at long-form technical narrative and structured JSON output.

lib/gemini.js: Gemini Wrapper Architecture

The planned lib/gemini.js module provides a single async function for each AI feature, keeping AI logic isolated from the Express routes:

// lib/gemini.js (planned)
const { GoogleGenerativeAI } = require('@google/generative-ai');

const genAI = new GoogleGenerativeAI(process.env.GEMINI_API_KEY);
const model = genAI.getGenerativeModel({ model: 'gemini-1.5-flash' });

/**
 * Generate fragility narrative after chaos injection.
 * @param {object} beforeScore - Original quality scores
 * @param {object} afterScore  - Post-chaos scores
 * @param {string[]} fragileFields - Fields most impacted by chaos
 */
async function getChaosNarrative(beforeScore, afterScore, fragileFields) {
  const prompt = `
    You are a data quality expert. A chaos test was run on a dataset.
    Before chaos: overall score ${beforeScore.overall_score}/100.
    After chaos:  overall score ${afterScore.overall_score}/100.
    Most impacted fields: ${fragileFields.join(', ')}.

    In 3-4 sentences, explain what this means for downstream AI models
    and data pipelines. Be specific about which model types are most at risk.
    Return only the narrative text, no preamble.
  `;
  const result = await model.generateContent(prompt);
  return result.response.text();
}

/**
 * Generate Python, JavaScript, and SQL fix code for detected issues.
 * @param {object[]} issues - Array of quality issues from /analyze
 * @param {string[]} columns - Column names from the dataset
 */
async function getFixSuggestions(issues, columns) {
  const prompt = `
    You are a data engineering expert. Given these data quality issues:
    ${JSON.stringify(issues, null, 2)}
    And these column names: ${columns.join(', ')}

    Generate fix code in three formats:
    1. Python (pandas)
    2. JavaScript (Node.js)
    3. SQL (PostgreSQL)

    Use the actual column names in the code. Return valid JSON:
    { "python": "...", "javascript": "...", "sql": "..." }
  `;
  const result = await model.generateContent(prompt);
  return JSON.parse(result.response.text());
}

/**
 * Generate AI Readiness verdict and explanation.
 * @param {object} scores - { overall_score, completeness, consistency, validity }
 * @param {object[]} issues - Array of quality issues
 */
async function getAIReadinessVerdict(scores, issues) {
  const prompt = `
    You are an ML pipeline expert. Rate this dataset's AI readiness.
    Quality scores: ${JSON.stringify(scores)}
    Issues found: ${issues.length} (${issues.filter(i=>i.severity==='critical').length} critical)

    Return valid JSON only:
    {
      "verdict": "AI Ready" | "Needs Improvement" | "Not AI Ready",
      "color": "green" | "yellow" | "red",
      "explanation": "2-3 sentence explanation",
      "top_risk": "The single biggest risk to AI pipeline performance"
    }
  `;
  const result = await model.generateContent(prompt);
  return JSON.parse(result.response.text());
}

module.exports = { getChaosNarrative, getFixSuggestions, getAIReadinessVerdict };
