## Priority 1b: Custom Rules Endpoint

### Prompt #1: Implement POST /custom-rules Endpoint

```
I need to implement the POST /custom-rules endpoint for our SysWisdom Guardrails platform.

CONTEXT:
- Project: Express.js backend (ES modules) with 9 existing endpoints
- Frontend: Vanilla JS SPA, no frameworks
- Database: JSON files (analyses.json, fix-library.json)
- Testing: Node.js built-in test runner (11/11 tests passing)

TASK:
Implement POST /custom-rules endpoint with these specs:

INPUT SCHEMA:
{
  name: string,           // e.g., "Mixed Types in Amount", "Missing Dates"
  column_pattern: string, // e.g., "Amount", "Date", or regex
  rule_type: string,      // "pattern", "datatype", "range", "custom"
  pattern: string,        // regex or rule description
  severity: string,       // "CRITICAL", "HIGH", "MEDIUM"
  auto_apply: boolean     // whether to auto-apply this rule
}

OUTPUT:
{
  rule_id: string,        // unique ID (e.g., "rule_2026_001")
  created_at: timestamp,
  name: string,
  severity: string,
  auto_apply: boolean
}

REQUIREMENTS:
1. Validate all input fields (return 400 if invalid)
2. Generate unique rule_id (timestamp + counter pattern)
3. Persist to data/custom-rules.json (create if doesn't exist)
4. Return 200 with rule object on success
5. Handle file I/O errors gracefully (500 on failure)
6. Use ES modules (import/export)
7. Follow code style of existing server.js endpoints

REFERENCE:
- Look at POST /fix-library endpoint (similar pattern)
- Use getCustomRulesFile() getter for dynamic file paths (like ANALYSES_FILE)
- Validation: required fields, severity enum, rule_type enum

Please implement this endpoint.
```

### Prompt #4: Integrate Custom Rules into Analyze Pipeline

```
I need to integrate custom rules into the POST /analyze endpoint so that uploaded data is validated against all active custom rules.

CURRENT BEHAVIOR:
- POST /analyze sends file to SysWisdom API
- API returns 3 issue types (Consistency, Completeness, Validity)
- normalizeIssues() converts to standard format

NEW BEHAVIOR:
- After API analysis, check data against all custom rules
- For each custom rule:
  - If column_pattern matches a column in the data
  - If pattern match found, create issue with custom rule severity
- Add custom rule issues to the normalized issues array

SCHEMA:
Custom rule issue should look like:
{
  issue_type: "Custom Rule Violation",
  field: rule.column_pattern,
  severity: rule.severity,
  description: rule.name,
  rule_id: rule.rule_id
}

IMPLEMENTATION:
- Load custom rules via getCustomRules()
- After normalizeIssues() call, iterate custom rules
- For each rule, match against data columns
- Add matching violations to issues array
- Return full issues array (API + custom rule violations)

TESTING:
- Manual test: Upload data, define custom rule, verify violations appear in Report

Please implement this integration.
```
