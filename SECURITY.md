# Security Policy

## Overview
SysWisdom GuardRails takes security seriously.

If you believe you have found a security vulnerability, please report it responsibly so we can investigate and fix it quickly.

## Reporting a Vulnerability
Please report all security concerns to:

- Email: info@syswisdom.ai
- Subject line recommendation: [SECURITY] GuardRails vulnerability report

Please include as much detail as possible:

- A clear description of the issue
- Affected component(s) and version/commit (if known)
- Reproduction steps or proof of concept
- Impact assessment (what could happen)
- Any suggested remediation
- Your preferred name/handle for acknowledgement (optional)

## Responsible Disclosure Expectations
We ask that you:

- Do not publicly disclose the issue before we have confirmed and addressed it
- Avoid accessing, modifying, or deleting data that is not your own
- Avoid service disruption, destructive testing, or privacy violations
- Share findings only with SysWisdom during the remediation window

We will:

- Treat your report confidentially
- Investigate in good faith
- Keep you informed through the process
- Coordinate disclosure timing with you when possible

## Response Process (Solo Startup Standard)
As a solo startup, we follow a pragmatic industry-aligned process with transparent timelines.

### 1) Acknowledgement
- Target: within 3 business days
- You will receive confirmation that we received your report

### 2) Triage and Validation
- Target: within 7 business days from acknowledgement
- We assess severity, impact, exploitability, and affected scope

### 3) Remediation Plan
- Critical/High: fix or mitigation target within 7-14 calendar days
- Medium: fix target within 30 calendar days
- Low: addressed in normal release cycle

If timelines must change due to complexity, we will communicate updated ETA.

### 4) Release and Verification
- We deploy a fix or mitigation
- We verify resolution and regression risk
- We may request reporter confirmation when appropriate

### 5) Coordinated Disclosure
- After fix availability, we may publish a brief advisory/changelog note
- Reporter credit is optional and provided only with consent

## Scope
This policy applies to this repository and maintained GuardRails services/integrations.

Out of scope (unless chained to a valid security issue):

- Social engineering or phishing attempts
- Denial-of-service testing or traffic flooding
- Physical attacks
- Reports requiring non-default insecure local setup only
- Issues in third-party services outside SysWisdom control (report those to the vendor)

## Safe Harbor
We support good-faith security research.

We will not pursue legal action for accidental, good-faith policy violations when:

- You act responsibly and avoid harm
- You promptly report the issue to info@syswisdom.ai
- You stop testing once risk is demonstrated

## Security Updates
Security fixes may be released as patch updates and noted in release notes/changelog when appropriate.
