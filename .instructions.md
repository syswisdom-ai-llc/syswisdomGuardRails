- **Frontend**: Vanilla JavaScript SPA (public/index.html)

- **Company**: SysWisdom.AI LLC, Georgia
- **API Backend**: Private web service (user-owned)

## Current Architecture

### Backend (server.js)
- **Module System**: ES modules (import/export)
- **Entry Point**: Dynamic detection (`import.meta.url` with fallback to `process.argv[1]`)
- **Endpoints** (7 total):
  1. `POST /analyze` — File upload to SysWisdom API, normalize issues
  2. `POST /approval` — Log human decision (approved/rejected)
  3. `GET /fix-library` — List all fixes sorted by votes (descending)
  4. `POST /fix-library` — Add new fix to library
  5. `POST /fix-library/vote` — Increment/decrement fix votes
  6. `GET /report/:id` — Generate plain-text quality report
  7. `GET /history` — Summarize all analyses (approved/rejected/pending counts)
  8. `GET /drift-analysis` — Monthly accuracy tracking + drift detection (>10% drop)
  9. `GET /training-export` — Export labeled dataset for ML retraining

### Data Files
- **`data/analyses.json`** — Records all uploaded files + API results
- **`data/fix-library.json`** — 7 seeded fixes with vote counts
- **Schema**: Each fix has `{ fix_id, issue_type, column, fix_description, votes, confidence, created_by, created_at }`

### Frontend (public/index.html)
- **Tabs**: Upload, Review, Fix Library, Report, History, Drift Monitor
- **Branding**: SysWisdom.AI throughout (title, header, footer with copyright)
- **Footer**: LLC, Georgia location, contact emails, links to Privacy/TOS

## Next Priority: Priority 1b — Custom Rules Endpoint

### Requirements
**New Endpoint: `POST /custom-rules`**
- **Purpose**: Allow users to define custom validation rules (name, pattern, column, severity)
- **Schema**:
  ```javascript
  {
    name: string,           // "Mixed Types in Amount", "Missing Dates", etc.
    column_pattern: string, // "Amount", "Date", or regex pattern
    rule_type: enum,        // "pattern", "datatype", "range", "custom"
    pattern: string,        // regex or description of rule
    severity: enum,         // "CRITICAL", "HIGH", "MEDIUM"
    auto_apply: boolean     // true if fix should apply automatically
  }
  ```

- **Return**: `{ rule_id, created_at, name, severity, auto_apply }`
- **Persist**: Save to `data/custom-rules.json` (lightweight database)
- **Behavior**: Apply rules to future analyses automatically

**New Endpoint: `GET /custom-rules`**
- **Purpose**: List all currently active custom rules
- **Return**: Array of rule objects with vote counts if applicable

### Implementation Tasks
1. Create `data/custom-rules.json` with seed rules (or empty array)
2. Add helper functions: `readCustomRules()`, `writeCustomRules()`, `generateRuleId()`
3. Implement `POST /custom-rules` endpoint with validation
4. Implement `GET /custom-rules` endpoint
5. Integrate custom rules into the `/analyze` pipeline (check custom rules against uploaded data)
6. Add Unit Test 12: `POST /custom-rules creates rule with rule_id`
7. Add Unit Test 13: `GET /custom-rules returns all rules in order`
8. Frontend integration: Add "Custom Rules" tab or modal in index.html

### Code Style
- **Language**: JavaScript (ES modules)
- **Naming**: camelCase for functions, UPPER_CASE for constants
- **Error Handling**: Return HTTP status codes (400 for validation, 404 for not found, 500 for server error)
- **File Paths**: Use getters for dynamic paths (e.g., `getCustomRulesFile()`)
- **Comments**: Brief JSDoc + inline comments for complex logic

## Wisdom Formula Context
The platform embodies: **Systemic Wisdom = (Experience / Wisdom) ^ Time**

- **Experience**: Each fix applied, each rule created, each analysis performed
- **Wisdom**: User expertise captured in custom rules + approved fixes
- **Time**: Iteration → learning → better automatic suggestions
- **Goal**: System learns faster as users apply fixes and define custom rules
